# Развёртывание своей PWA на GitHub Pages

## Репозиторий приложения

1. Создайте fork репозитория приложения. Скопируйте ветки PWA: при создании форка не ограничивайтесь только `main`, если PWA находится в `pwa/development`.
2. Для самостоятельного экземпляра удобно назначить `pwa/development` веткой по умолчанию в Settings → General → Default branch. В ней workflow `Publish PWA to GitHub Pages` запускается вручную. Не переносите приложение в `main` только ради публикации: там могут быть workflow других платформ.
3. Разрешите GitHub Actions в форке. Settings → Pages → Build and deployment → Source: **GitHub Actions**. Если окружение `github-pages` ограничивает ветки, разрешите ветку, из которой публикуете.
4. Actions → **Publish PWA to GitHub Pages** → **Run workflow**, выберите свою ветку с PWA. Дождитесь успешного завершения тестов и Deploy GitHub Pages.
5. Откройте адрес из результата Deploy или Settings → Pages. Кнопка «Инструкция» открывает руководство этого же экземпляра.

Имя репозитория менять можно: путь берётся из `actions/configure-pages` (`base_path`). Поддерживаются `/имя-репозитория/` и `/` для пользовательского сайта или отдельного домена, настроенного в Pages. Ссылки на руководство относительные. Репозиторий приложения не требует личного токена для публикации: workflow использует выданный GitHub `GITHUB_TOKEN` с contents:read, pages:write и id-token:write. Настройки домена/DNS выполняются отдельно в Pages.

В исходном проекте `pwa/publish` публикуется автоматически при push, а `pwa/development` — вручную. Выберите один порядок выпуска у себя; учитывайте triggers перед push. Native workflow включать для выпуска PWA не требуется.

## Данные и доступ

Приложение работает с локальной IndexedDB без настройки синхронизации. Данные и токены исходного автора не включены в исходники форка. Чтобы обмениваться между устройствами, создайте свой отдельный **приватный** репозиторий с README и fine-grained token с **Contents: Read and write** только для него. Введите репозиторий, ветку и токен в настройках PWA, проверьте подключение, выполните синхронизацию на каждом устройстве. Подробные шаги — в разделе GitHub инструкции приложения.

Запоминание токена включается добровольно на каждом устройстве; токен не экспортируется с задачами. Данные читаются через API, а не Pages. При изменении домена/пути старые локальные записи автоматически не переносятся: сначала скачайте JSON-копию и восстановите её в новом экземпляре либо настройте обмен через тот же приватный репозиторий.

## Что проверить после публикации

Создание задачи, запуск/пауза, описание «Далее», открытие своей инструкции, сохранение после перезагрузки и настоящая офлайн-перезагрузка. Диктовка требует отдельной загрузки модели из внешнего источника; проверьте доступность загрузки в своём окружении. Установка, уведомления и микрофон зависят от браузера и устройства. Поддержка других имён проверяется преобразованиями путей; это не обещание работоспособности любых настроек хостинга.

Если используете собственный Node-сервер вместо Pages, `pwa/server.cjs` требует `PORT` и `CLOUDCLI_DATA_DIR` (контракт runtime); данные задач при этом остаются в браузере. Для HTTPS используйте свой reverse proxy. Локальные сборки/стадирование не требуются; правило стадирования артефактов только в GitHub Actions сохраняется.
