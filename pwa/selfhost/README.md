# Отдельный серверный экземпляр PWA

Ветка `pwa/selfhost-sync`. Тестовый вариант для одного владельца и нескольких устройств. Не переключает GitHub Pages и не меняет desktop/Android. Приложение остаётся offline-first; сервер хранит общий причинный документ v2 в SQLite. Парольного входа и нескольких независимых пользователей в этом выпуске нет: отдельный отзывной ключ на каждое устройство. Сохранение ключа в браузере добровольное; это bearer-доступ к общей базе, не шифрование данных на сервере.

## Требуется

- Linux VPS, ориентировочно 1–2 CPU / 2 ГБ RAM / 20 ГБ SSD для личного экземпляра.
- Node.js 24 LTS (тесты совместимы также с Node22.23), встроенный `node:sqlite`; npm-зависимостей для runtime нет.
- Поддомен, DNS, HTTPS reverse proxy Caddy или Nginx. Поддерживается установка в корне отдельного origin, не в подпапке.
- Постоянный **локальный** диск для SQLite, права записи только у службы. Не размещать WAL SQLite на сетевом файловом хранилище.
- Отдельное место для копий базы за пределами VPS.

В архиве сохраняется `pwa/` и `docs/user-guide/`.

## 2. Постоянный каталог и служба

Создать отдельного системного пользователя `tasktimer` без интерактивного входа. Скопировать пример `tasktimer.service` в systemd, заменить пути и домен. `CLOUDCLI_DATA_DIR` обязателен и указывает на постоянный `/var/lib/tasktimer`, вне исходников и публичного дерева. Не использовать `/tmp` для настоящих данных.

Запуск: `node /opt/tasktimer/current/pwa/selfhost/server.cjs`.
Обязательные переменные: `PORT=18081`, `CLOUDCLI_DATA_DIR=/var/lib/tasktimer`, `TASKTIMER_PUBLIC_ORIGIN=https://timer.example.org` (без слеша). Локальный HTTP разрешён только для loopback `localhost`/`127.0.0.1` при разработке; удалённый сервер требует HTTPS.

Приложение слушает 0.0.0.0. Закрыть порт18081 от внешней сети; снаружи доступны только HTTPS и административный SSH. Reverse proxy направляет запросы на127.0.0.1:18081. API передаёт Authorization, If-Match, If-None-Match, ETag без удаления. Не кешировать `/api/*`, `/sw.js`, `/release-notes.json`. Не записывать Authorization или тела запросов в журналы.

## 3. HTTPS

Пример Caddyfile:

```caddy
 timer.example.org {
   reverse_proxy 127.0.0.1:18081
 }
```

Указать настоящий DNS, обеспечить доступ для выпуска/продления сертификата и настроить Caddy. API принимает только свой origin, без CORS и cookie; проверяет bearer-ключ. Это не прокси к GitHub.

## 4. Ключи устройств

На сервере от имени службы, с тем же CLOUDCLI_DATA_DIR:

```sh
node /opt/tasktimer/current/pwa/selfhost/admin.cjs add-device 'Мой телефон'
node /opt/tasktimer/current/pwa/selfhost/admin.cjs devices
node /opt/tasktimer/current/pwa/selfhost/admin.cjs revoke DEVICE_ID
```

`add-device` однократно покажет случайный ключ. Передать его владельцу устройства защищённым способом. Не отправлять в чат с агентом, не сохранять в Git, CI variables или журналах. База хранит SHA256 случайного256-bit ключа, а не сам ключ. `devices` показывает только ID/метку/дату/отзыв. Ключи не имеют автоматического срока действия; при компрометации отозвать и выпустить новый. Отзыв прекращает дальнейший обмен, но не стирает локальные задачи с потерянного устройства.

В PWA открыть настройки, ввести ключ, проверить подключение и синхронизировать. На каждом устройстве свой ключ. Автоматический режим выключен до включения пользователем.

## 5. Перенос и проверка

Сначала тестировать на копии данных, не на единственной рабочей базе. При смене домена IndexedDB/ключи не переносятся автоматически.

Для простого теста: скачать JSON старой PWA, импортировать **один раз на первом устройстве** новой PWA, затем обменять с новым сервером. На втором устройстве только скачать обменом. Это перенос состояния, без непрерывности прежней причинной истории; старую GitHub-базу не объединять обратно с новой без отдельной миграции.

Для непрерывного переноса v2: после финальной синхронизации получить существующий `data/state.v2.json` из своего приватного репозитория и условно загрузить в **пустой** серверный `/api/sync`, не меняя ID/ops/отметки удаления. На сервере от имени службы выполнить `node /opt/tasktimer/current/pwa/selfhost/admin.cjs import-v2 /private/exported-state.v2.json`. Команда проверяет формат и отказывается писать в непустую базу; ключи доступа ей не нужны. Экспорт хранить приватно, после проверки миграции убрать с сервера в архив резервных копий. Сам PWA API не может скачать GitHub-данные без вашего токена. Проверить format/version и задачи после загрузки, токены не переносить. До миграции сохранить JSON с каждого устройства и исходный v2-документ.

Чеклист: HTTPS/установка; создание/пауза/завершение; два устройства; одновременно разные поля; конфликт одного поля; удаление сессии; offline/reconnect; автообмен10s/120s; перезагрузка; отзыв ключа; неверный ключ; рестарт сервера; резервная копия и восстановление отдельно. Существующую PWA не удалять до сверки. Ошибки диска/квоты возвращают503, не сбрасывая базу.

## 6. Резервирование и обновление

```sh
node /opt/tasktimer/current/pwa/selfhost/admin.cjs backup /absolute/backup/new-copy.sqlite
```

Использует SQLite Online Backup: согласованная копия при работающем приложении, файл0600. Не копировать только `.sqlite` из работающего WAL-режима вручную. Копия содержит задачи и хеши ключей — хранить приватно, шифровать при переносе и отправлять за пределы VPS. Не выдавать копии через HTTP.

Восстановление проверять в **отдельном каталоге и экземпляре**, без перезаписи рабочей базы. При настоящем восстановлении остановить службу, сохранить текущие sqlite/WAL/SHM отдельно, восстановить согласованную копию как `tasktimer.sqlite`, проверить права, запустить и сверить. Не оставлять старые WAL/SHM рядом с восстановленным main-файлом.

Перед обновлением — backup; затем переключить каталог кода и перезапустить. SQLite остаётся в прежнем каталоге. Перед откатом сверять совместимость user_version; сервер отказывается открывать неизвестную будущую схему. Публичные статические файлы и Service Worker при selfhost имеют отдельную вычисленную ревизию.

## Границы первого выпуска

API: GET/PUT `/api/sync`, max20МиБ, причинный форматv2, обязательный If-Match/If-None-Match, transaction/CAS защищает разные процессы. Статика публична; без ключа нет доступа к серверным задачам. Нет регистрации, WebSocket, push-сервера, фонового выполнения закрытой PWA, веб-панели администрирования и серверного распознавания речи. История операций растёт; автоматическое удаление причинной истории не реализовано. Прежде чем лимит будет достигнут, потребуется отдельная безопасная компактизация.

## Обновление исходников 12 ноября 2026

Перенесены актуальные функции PWA: автоматическая сортировка без остановки сессии, счётчики вкладок, единый таймер концентрации, понятные конфликты и исправление запуска с уже сохранённым конфликтом. Автообмен проверяет изменения каждые 30 секунд в видимом приложении; изменения отправляются через 10 секунд. Запуск/пауза/завершение таймера применяются после успешного обмена, включая нерешённые конфликты других полей. В закрытом или приостановленном браузере немедленная доставка не гарантируется.

Серверный транспорт остаётся `/api/sync` с ключами устройств, ETag и SQLite. GitHub-токены и GitHub Contents API серверной версии не нужны. Предел серверного документа остаётся 20 МиБ; изменение схемы SQLite и миграция данных не требуются.
