# TaskTimer PWA

Версия исходников — `0.11.7`, синхронизирована с проектом TaskTimer. Это неопубликованный PWA-клиент; номер не означает выпуск PWA-релиза.

Первый локальный клиент по этапам 1–5: задачи, таймер, история и редактор сессий, концентрация, JSON-резервные копии и устанавливаемая оболочка. WebDAV v2 и офлайн-диктовка пока не реализованы. Формат старого desktop/Android JSON автоматически не импортируется: импорт принимает только проверенную схему PWA `schemaVersion: 1`.

## Устройство

- `public/model.mjs` — операции над задачами, сессиями и концентрацией, проверка резервных копий. Срок концентрации хранится явно; после сна сессия закрывается по сохранённому сроку.
- `public/repository.mjs` — IndexedDB, база `tasktimer-pwa`, store `state`, ключ `current`. Чтение актуального состояния и запись выполняются в одной `readwrite`-транзакции. BroadcastChannel и возврат фокуса обновляют вкладки. Ошибки хранилища не сбрасывают данные.
- `public/app.mjs`, `index.html`, `styles.css` — русский интерфейс; изменения считаются сохранёнными после завершения транзакции.
- `public/pwa.mjs`, `sw.js`, `manifest.webmanifest`, `icons/` — установка, запрос постоянного хранения, кеш статической оболочки и предложение обновления в настройках. Перед принятым обновлением событие `tasktimer:before-update` ждёт незавершённые записи через `detail.waitUntil(promise)`. Несохранённые поля формы пользователь подтверждает перед перезагрузкой.
- `pwa/server.cjs` раздаёт только явно перечисленные публичные файлы. Пользовательские задачи на сервер не отправляются. Сервер требует `CLOUDCLI_DATA_DIR`, но приложение не пишет туда данные. Значения секретов и файлы конфигурации не раздаются.

Сервер вычисляет ревизию service worker по содержимому публичных файлов: отдельный шаг сборки не нужен. Worker кеширует только свои статические пути без query и Authorization; внешние запросы, записи и неизвестные пути не перехватываются. Установка worker ожидает загрузку всей оболочки. Обновление не активируется принудительно без согласия пользователя; сохраняются текущий и два предыдущих кеша.

## Запуск исходников

Из корня репозитория `timerapp`, в разрешённой среде с доступным TCP:

```sh
tasktimer_test_data=$(mktemp -d /tmp/tasktimer-pwa-data.XXXXXX)
CLOUDCLI_DATA_DIR="$tasktimer_test_data" PORT=18081 node pwa/server.cjs
```

Это запуск интерпретируемых исходников, не сборка. Сервер слушает `0.0.0.0` и заданный `PORT`. На платформе переменные предоставляет runtime, команда остаётся `npm start` → `node server.js`; внешний адаптер `server.js` подключает `timerapp/pwa/server.cjs`. Для самостоятельного checkout достаточно Node.js, зависимости npm не нужны. Не создавать и не изучать `/data` в рабочем окружении. Для настоящей установки и service worker требуется HTTPS либо разрешённый браузером локальный secure context.

**Любые сборки и повторы — только в GitHub Actions после отдельного явного разрешения.** Локальные сборки, Docker build, создание пакетов, push и публикация не входят в запуск/проверку PWA.

## Проверки без сборки

Из корня репозитория `timerapp`:

```sh
UV_THREADPOOL_SIZE=1 NODE_OPTIONS=--v8-pool-size=1 node --test \
  pwa/tests/model.test.mjs \
  pwa/tests/server.test.cjs \
  pwa/tests/sw.test.cjs
```

`server.test.cjs` использует временный Unix socket, настоящий HTTP parser и production-обработчик, не меняя привязку production-сервера. `sw.test.cjs` проверяет контракты обработчиков service worker в VM: успешную и неуспешную установку, чтение кеша, отказ сети, исключённые запросы, явную активацию и очистку старых кешей. **Это не браузерная проверка офлайн-запуска.**

`tests/browser.test.cjs` содержит браузерные проверки интерфейса/IndexedDB. Playwright закреплён в `pwa/package.json` и lockfile точной версией `1.63.0`; зависимости нужны только для тестов. Установка готового Chromium не является сборкой приложения.

Подготовка на новой машине (из `timerapp/pwa`):

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
```

Для повторного использования уже загруженного браузера в текущем рабочем окружении, без скачивания:

```sh
PLAYWRIGHT_BROWSERS_PATH=/tmp/tasktimer-pwa-browsers \
UV_THREADPOOL_SIZE=1 NODE_OPTIONS=--v8-pool-size=1 npm test
```

Если npm cache по умолчанию недоступен для записи, добавить к `npm ci` аргумент `--cache /tmp/tasktimer-pwa-npm-cache`. `npm run test:unit` запускает проверки модели, HTTP и service worker без Chromium. Все тестовые файлы запускаются последовательно для ограничения потребления ресурсов. Ограничения сетевого окружения и реальных устройств фиксируются отдельно, без объявления таких сценариев пройденными.

## Приёмка на телефонах

В Chrome Android и Safari iPhone отдельно проверить:

- Установку с реального HTTPS-адреса и открытие с главного экрана.
- Повторный запуск в авиарежиме после успешного сохранения оболочки.
- Таймер после закрытия приложения и блокировки экрана; концентрацию после истечения срока во сне.
- Редактирование сессии, экспорт, восстановление копии и отсутствие потери данных после обновления приложения.
- Принятое и отложенное обновление, включая активный таймер и открытые формы.
- Недостаток места, доступность постоянного хранения, понятные ошибки без сброса данных.
- Уведомление при открытом приложении; фоновые и закрытые состояния фиксировать отдельно. Точный офлайн-сигнал при закрытом браузере не гарантируется.

Публичный HTTPS-адрес в доступных метаданных пока не обнаружен; проверка live URL и физические устройства остаются обязательными перед заявлением полной готовности.

Следующие этапы: общий WebDAV v2 с Android/desktop (causal revisions, tombstones, конфликты, условный PUT и реальные CORS-проверки) и проверка готового sherpa-onnx WASM/русской модели на телефонах. Cloud SpeechRecognition не используется как подмена офлайн-распознавания. Отправка времени в Битрикс24 в этот клиент не включена.
