# TaskTimer PWA

Версия исходников — `0.11.7`, синхронизирована с проектом TaskTimer. Это неопубликованный PWA-клиент; номер не означает выпуск PWA-релиза.

Неопубликованный клиент: задачи, таймер, история и редактор сессий, концентрация, JSON-резервные копии, WebDAV v2 и интерфейс офлайн-диктовки. Реальные телефонные проверки, CORS пользовательского WebDAV и публичный HTTPS остаются непроверенными. Импорт через файл принимает PWA `schemaVersion: 1`; первичная миграция старого desktop/Android JSON выполняется отдельно при WebDAV-синхронизации.

## Устройство

- `public/model.mjs` — операции над задачами, сессиями и концентрацией, проверка резервных копий. Срок концентрации хранится явно; после сна сессия закрывается по сохранённому сроку.
- `public/repository.mjs` — IndexedDB, база `tasktimer-pwa`, store `state`, ключ `current`. Чтение актуального состояния и запись выполняются в одной `readwrite`-транзакции. BroadcastChannel и возврат фокуса обновляют вкладки. Ошибки хранилища не сбрасывают данные.
- `public/sync-protocol.mjs`, `sync-controller.mjs`, `webdav-client.mjs` — причинные операции, сохранённые удаления/конфликты, прямой HTTPS WebDAV и условная запись. Локальный журнал и проекция фиксируются одной транзакцией; сеть не держит IndexedDB транзакцию.
- `public/voice.mjs`, `voice-ui.mjs`, `voice-worker.mjs`, `voice-worklet.mjs` — загрузка проверенной модели, микрофон, обработка в worker, добавление редактируемого результата в название, описание или комментарий.
- `public/app.mjs`, `index.html`, `styles.css` — русский интерфейс; изменения считаются сохранёнными после завершения транзакции.
- `public/pwa.mjs`, `sw.js`, `manifest.webmanifest`, `icons/` — установка, запрос постоянного хранения, кеш статической оболочки и предложение обновления в настройках. Перед принятым обновлением событие `tasktimer:before-update` ждёт незавершённые записи через `detail.waitUntil(promise)`. Несохранённые поля формы пользователь подтверждает перед перезагрузкой.
- `pwa/server.cjs` раздаёт только явно перечисленные публичные файлы. Пользовательские задачи на сервер не отправляются. Сервер требует `CLOUDCLI_DATA_DIR`, но приложение не пишет туда данные. Значения секретов и файлы конфигурации не раздаются.

Сервер вычисляет ревизию service worker по содержимому публичных файлов: отдельный шаг сборки не нужен. Worker кеширует оболочку и отдельно установленные проверенные файлы голосового runtime; автоматически модель не скачивает. Он обслуживает только известные статические пути без query и Authorization; внешние запросы, записи и неизвестные пути не перехватываются. Установка worker ожидает загрузку всей оболочки. Обновление не активируется принудительно без согласия пользователя; сохраняются текущий и два предыдущих кеша.

## Запуск исходников

Из корня репозитория `timerapp`, в разрешённой среде с доступным TCP:

```sh
tasktimer_test_data=$(mktemp -d /tmp/tasktimer-pwa-data.XXXXXX)
CLOUDCLI_DATA_DIR="$tasktimer_test_data" PORT=18081 node pwa/server.cjs
```

Это запуск интерпретируемых исходников, не сборка. Сервер слушает `0.0.0.0` и заданный `PORT`. На платформе переменные предоставляет runtime, команда остаётся `npm start` → `node server.js`; внешний адаптер `server.js` подключает `timerapp/pwa/server.cjs`. Для самостоятельного checkout достаточно Node.js, зависимости npm не нужны. Не создавать и не изучать `/data` в рабочем окружении. Для настоящей установки и service worker требуется HTTPS либо разрешённый браузером локальный secure context.

**Любые сборки и повторы — только в GitHub Actions после отдельного явного разрешения.** Локальные сборки, Docker build, создание пакетов, push и публикация не входят в запуск/проверку PWA.

## Проверки без сборки

Из корня репозитория `timerapp`:

```sh
UV_THREADPOOL_SIZE=1 NODE_OPTIONS=--v8-pool-size=1 node --test \
  pwa/tests/model.test.mjs \
  pwa/tests/server.test.cjs \
  pwa/tests/sw.test.cjs
```

`server.test.cjs` использует временный Unix socket, настоящий HTTP parser и production-обработчик, не меняя привязку production-сервера. `sw.test.cjs` проверяет контракты обработчиков service worker в VM: успешную и неуспешную установку, чтение кеша, отказ сети, исключённые запросы, явную активацию и очистку старых кешей. **Это не браузерная проверка офлайн-запуска.**

`tests/browser.test.cjs` содержит браузерные проверки интерфейса/IndexedDB. Отдельный `tests/live-offline.check.cjs` подготовлен для ручного GitHub workflow: настоящий TCP-сервер из временной копии исходников, настоящий service worker, офлайн-перезагрузка с активным таймером, ожидание обновления до согласия и офлайн-перезагрузка обновлённой оболочки. Внешний watchdog завершает группу процессов через 110 секунд, CI дополнительно ограничивает шаг 120 секундами. Этот сценарий не входит в `npm test`; он успешно прошёл в разрешённом GitHub Actions запуске 2026-10-01. Реальный публичный HTTPS и физические устройства он не заменяет. Playwright закреплён в `pwa/package.json` и lockfile точной версией `1.63.0`; зависимости нужны только для тестов. Установка готового Chromium не является сборкой приложения.

Подготовка на новой машине (из `timerapp/pwa`):

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
```

Для повторного использования уже загруженного браузера в текущем рабочем окружении, без скачивания:

```sh
PLAYWRIGHT_BROWSERS_PATH=/tmp/tasktimer-pwa-browsers \
UV_THREADPOOL_SIZE=1 NODE_OPTIONS=--v8-pool-size=1 npm test
```

Если npm cache по умолчанию недоступен для записи, добавить к `npm ci` аргумент `--cache /tmp/tasktimer-pwa-npm-cache`. `npm run test:unit` запускает модель, протокол, транспорт, синхронизацию, установку голоса, HTTP и service worker без Chromium. Реальная WASM-инференция исключена из обычного набора: `tests/voice-inference.check.cjs` требует заранее скачанных файлов и имеет внешний 180-секундный watchdog, завершающий группу браузерных процессов. Не запускать её одновременно с другим Chromium. Все тестовые файлы запускаются последовательно для ограничения потребления ресурсов. Ограничения сетевого окружения и реальных устройств фиксируются отдельно, без объявления таких сценариев пройденными.

## Приёмка на телефонах

В Chrome Android и Safari iPhone отдельно проверить:

- Установку с реального HTTPS-адреса и открытие с главного экрана.
- Повторный запуск в авиарежиме после успешного сохранения оболочки.
- Таймер после закрытия приложения и блокировки экрана; концентрацию после истечения срока во сне.
- Редактирование сессии, экспорт, восстановление копии и отсутствие потери данных после обновления приложения.
- Принятое и отложенное обновление, включая активный таймер и открытые формы.
- Недостаток места, доступность постоянного хранения, понятные ошибки без сброса данных.
- Уведомление при открытом приложении; фоновые и закрытые состояния фиксировать отдельно. Точный офлайн-сигнал при закрытом браузере не гарантируется.

Публичный HTTPS-адрес в доступных метаданных пока не обнаружен; проверка live URL и физические устройства остаются обязательными перед заявлением полной готовности.

## WebDAV и резервные копии

В настройках вводится HTTPS-адрес **старого файла**. Новый ресурс получается добавлением `.v2.json`, например `tasks.json.v2.json`. Логин/пароль остаются только в памяти страницы, не попадают в IndexedDB или экспорт. Сервер приложения не является прокси. WebDAV должен разрешать CORS для origin приложения: GET/PUT, Authorization, Content-Type, If-Match, If-None-Match; `Access-Control-Expose-Headers: ETag`. Перенаправления запрещены. Для v2 нужен сильный ETag; при создании используется `If-None-Match: *`. После 412 максимум три попытки чтения/слияния/условной записи.

При отсутствующем v2 старый файл читается без записи и без обязательного ETag; копия его задач и локальные данные до миграции сохраняются в IndexedDB. Импорт выполняется один раз независимой причинной ветвью. При существующем v2 старый файл заново не импортируется. Старые клиенты не участвуют в новом обмене — Android/desktop должны поддерживать v2. Данные пользователя на реальном WebDAV этой реализацией пока не проверены.

Удаления и альтернативные значения сохраняются в журнале. Конфликты выбираются в настройках. Если слияние даёт несколько работающих таймеров, применение проекции блокируется; пользователь явно выбирает одну сессию, остальные закрываются текущим временем с сохранением истории. При правке того же поля в другой вкладке открытая форма сохраняет черновик и предлагает явное подтверждение перезаписи.

Экспорт после включения синхронизации содержит `syncDocument` со всеми скрытыми удалениями/конфликтами, но не локальный идентификатор писателя и не пароль. Восстановление такой копии объединяет журналы, создавая новый локальный идентификатор. Обычная старая PWA-копия без журнала заменяет проекцию только после явного подтверждения; при действующей синхронизации изменения становятся новыми операциями. Копия задач legacy также включается в экспорт; неизвестные поля задач и сессий сохраняются. Старые UI/настройки оболочки не копируются: они могут содержать исторические пароли. Приоритет PWA передаётся общим `daily_priorities[day]`, обычный 4 — отсутствие записи, `keep_priority` сохраняется.

## Голос

Официальный готовый sherpa-onnx WASM 1.12.32 и Zipformer RU INT8 2025-04-20 закреплены по хешам; происхождение в `public/voice-assets/PROVENANCE.md`. Движок и модель занимают 85 099 899 байт загрузки. Модель загружается явно, проверенные части остаются для повтора, место проверяется до скачивания. Удаление модели не затрагивает задачи. Речь не отправляется в облачный сервис.

Фрагмент до 60 секунд записывается с разрешения пользователя, затем микрофон освобождается и worker распознаёт запись. Результат можно отредактировать, продолжить диктовку и добавить в поле; отмена не меняет исходное поле. Офлайн требует предварительной установки оболочки и модели; браузер может очистить кеш при нехватке места. На физических Android/iPhone работоспособность и потребление памяти ещё необходимо проверить.

Проверен реальный русский WAV через готовый WASM в Node и, 2026-10-01, в настоящем Chromium worker в GitHub Actions: сценарий подтвердил результат «я тебя люблю» после установки проверенных файлов модели и блокировки её сетевой загрузки на этапе распознавания. Микрофон и память физических телефонов этим не проверены. Браузерный сценарий голосового интерфейса использует подмену движка и подтверждает только добавление/отмену, не качество распознавания. Cloud SpeechRecognition не используется. Отправка времени в Битрикс24 в этот клиент не включена.


## Отдельная проверка PWA в GitHub

`.github/workflows/pwa-check.yml` запускается только вручную после отдельного разрешения. Он последовательно проверяет PWA-тесты, настоящий Service Worker с офлайн-перезагрузкой и принятием обновления; параметр `voice_inference=true` дополнительно скачивает закреплённую русскую модель, проверяет SHA-256 и запускает реальное распознавание в browser worker. Без этого параметра голосовая инференция не проверяется. Журналы, в том числе голосовой проверки, сохраняются в `pwa-verification-reports`; этапы ограничены watchdog/timeout.

Этот workflow не запускает Android/Python/desktop, не собирает пакеты и не публикует приложение. В отличие от `sync-pwa-check.yml`, он не проверяет остальные клиенты. Браузерные проверки используют тестовый origin и локальный сервер GitHub runner: они не создают публичный HTTPS-адрес для телефона и не заменяют установку, микрофон, CORS WebDAV и офлайн-проверку на реальных Android/iPhone.

Наличие файла в рабочей ветке ещё не гарантирует кнопку «Run workflow»: GitHub обычно требует регистрацию workflow в default-ветке. Слияние в main/master и запуск проверки этим описанием не разрешаются; способ одного запуска согласуется отдельно.


Разрешённая PWA-only проверка [GitHub Actions 36843505302](https://github.com/alexandrgert/timerapp_exp/actions/runs/36843505302) завершилась успешно с первой попытки: обычные PWA-тесты, настоящий SW с офлайн-перезагрузкой/обновлением и реальная WASM-инференция прошли. Для одного запуска использовалась отдельная ветка с точечным push-триггером; основной workflow остался ручным. [Отчёт и ограничения проверки](docs/verification-2026-10-01.md). Новых запусков это не разрешает.

## Постоянный адрес через GitHub Pages

Подготовлен ручной `.github/workflows/pwa-pages.yml`. До первого запуска владелец репозитория должен открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**. Если среда **Settings → Environments → github-pages** ограничивает ветки, нужно разрешить согласованную рабочую ветку `android/session-editor` (или отдельную согласованную ветку публикации). Требуемые approvals среды сохраняются. Наличие файла только в рабочей ветке может не дать кнопку Run workflow: способ регистрации/одного запуска согласуется отдельно; автоматического слияния в main/master нет.

После успешного deployment ожидаемый постоянный адрес — `https://alexandrgert.github.io/timerapp_exp/`. Пока deployment не выполнен и URL не проверен, это **целевой адрес, а не подтверждённая работающая публикация**. Он отличается от текущего Node-приложения: IndexedDB принадлежит другому origin, поэтому данные переносятся явным экспортом/импортом резервной копии.

`pwa/scripts/pages-stage.mjs` выполняет файловую подготовку только в GitHub Actions. Он копирует allowlist публичных файлов в `_site`, добавляет базовый путь `/timerapp_exp/`, подставляет commit SHA в Service Worker и разделяет имена кешей/IndexedDB/голосовой блокировки по пути приложения. Корневые Node-исходники и vendor JS/WASM остаются побайтно неизменными; SHA-проверки голосовых файлов сохраняются. Никакие Node-серверы, исходники native-клиентов, тесты или пользовательские данные не публикуются. Локально допускаются только чистые тесты преобразования в памяти, без создания `_site`/архивов.

Статическая страница получает CSP/referrer через поддерживаемые HTML meta-теги. Pages не использует HTTP-заголовки `server.cjs`; `frame-ancestors`/X-Frame-Options нельзя обеспечить этим meta CSP. После публикации проверить HTTPS, завершающий `/`, MIME `.mjs`/`.wasm`, scope Service Worker, установку/офлайн и обновление на телефонах, а также CORS пользовательского WebDAV для нового origin. Публикация не заменяет эти проверки и не запускает Android/desktop.
