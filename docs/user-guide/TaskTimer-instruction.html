1. Открыть приложение и начать работу

Откройте свой экземпляр TaskTimer PWA. Вернуться к приложению можно из опубликованной инструкции. Пункт «Инструкция» в верхней панели открывает это руководство в новой вкладке. Можно работать в браузере или установить приложение через меню браузера — если установка поддерживается, также доступна кнопка «Установить приложение» в настройках.

  1. Нажмите «Новая задача».
  2. Введите название и выберите «Добавить и начать».
  3. Когда закончите работу на время, нажмите «Пауза». Когда задача выполнена полностью — «Завершить». Подтвердите завершение в окне результата; после сохранения окно истории задачи закроется автоматически.
  4. В конце дня откройте «Отчёт дня».

Задачи хранятся в этом браузере на этом устройстве. Установка на другой компьютер сама по себе не переносит записи. Для переноса используйте резервную копию или настроенную синхронизацию.

После первого успешного открытия и кеширования приложение может работать без интернета. Для первоначальной загрузки, обновлений и обмена WebDAV нужна сеть.

2. Создать и изменить задачу

  1. Нажмите «Новая задача».
  2. Заполните название. Описание и результат — по необходимости.
  3. Выберите дату и приоритет: 1 — высокий, 4 — обычный; 2 и 3 — промежуточные уровни.
  4. «Добавить» сохраняет запись без запуска времени. «Добавить и начать» сохраняет запись и запускает таймер; другая работающая задача приостанавливается.

Кнопка «Изменить» открывает редактор существующей задачи. Он показывает дату и приоритет дня, выбранного в списке. Изменение приоритета относится к этому дню и не переписывает прошлые дни. Изменение только текста или приоритета не переносит исходную дату задачи; явное изменение даты сохраняется отдельно.

«Отмена» закрывает форму без сохранения. Если данные успели измениться в другой вкладке, приложение предупреждает о конфликте: проверьте значения перед выбором «Сохранить мой вариант поверх».

При создании задачи на будущую дату выбранный приоритет сохраняется и для этой даты, и для сегодняшнего отображения. «Добавить» оставляет задачу в плане на выбранную дату; «Добавить и начать» также запускает таймер сейчас. Опция сохранения приоритета продолжает управлять последующим переносом между днями.

3. Найти задачу, составить план и задать порядок

Во вкладке «Завершённые» находятся только завершённые записи. Фильтры «Дата создания» и «Дата завершения» выбирают записи за конкретный локальный день; их можно использовать по отдельности или вместе. Пустое поле не ограничивает дату. Дата создания — фактическое создание записи, а не день плана. Поиск по названию и фильтры приоритета продолжают работать.

При режиме «Вручную» новая запись вставляется после последней незавершённой записи того же приоритета в текущем списке. Если таких нет — после записей более высокого приоритета. Остальные записи не переставляются. Работающая задача остаётся сверху.

Рядом с «Сегодня», «В работе» и «Все» в скобках показано число записей соответствующего списка с учётом поиска и фильтра приоритетов. На вкладке «Все» дополнительно показано, сколько записей открыто и сколько завершено. Счётчики обновляются при изменении записей и фильтров.

ЭлементЧто делает
СегодняПоказывает задачи в плане на сегодня.
В работеВсе незавершённые задачи, включая не включённые в план.
ВсеНезавершённые и завершённые записи.
ДатаПри выборе календарной даты показывает задачи с учтённым временем за этот день. Для просмотра всех записей затем нажмите «Все».
ПоискИщет по названию задачи.
Фильтр 1–4Управляет видимостью приоритетов.

Для массовой смены приоритета отметьте задачи флажками и нажмите нужную цифру рядом с «Выбрано». После назначения приоритета или переключения «Сегодня / В работе / Все» выделение сбрасывается.

Сортировка: выбор «Приоритет 1 → 4» или «Приоритет 4 → 1» включает автоматическое поддержание порядка по приоритету выбранного дня. Новые записи, изменение приоритета и получение изменений из другой вкладки или синхронизации перестраивают список автоматически. При равных приоритетах сохраняется уже выстроенный порядок.

Смена режима сортировки и перетаскивание меняют только порядок: они не останавливают и не перезапускают таймер задачи. Автоостановка по напоминанию, окончание концентрации и переход суток обрабатываются отдельно.

Выбранное направление запоминается на этом устройстве и восстанавливается после перезагрузки. Переключение вкладок и фильтров не отключает автоматическую сортировку. На «Вручную» текущий порядок фиксируется для дальнейшего редактирования; если включены поиск или фильтр, сохраняется порядок только показанных незавершённых задач, скрытые сохраняют свои места.

Список можно поправить перетаскиванием сразу из автоматического режима. Первое успешное перемещение фиксирует текущий порядок и переключает режим на «Вручную»; ручной порядок сохраняется после перезагрузки. Работающая задача всегда закреплена сверху. После паузы она возвращается в позицию по выбранному приоритету в автоматическом режиме либо в сохранённый порядок в ручном.

Тяните запись за значок ⠿ слева. При работе с клавиатурой установите фокус на этот значок и используйте стрелки вверх/вниз. Работающая задача всегда сверху. Завершённые — внизу по времени завершения: последняя завершённая ниже остальных; их перетаскивание отключено.

«Из плана» убирает задачу из плана выбранного дня, но не удаляет историю. Найти её можно во «В работе» или «Все», вернуть — кнопкой «В план».

Замочек рядом с приоритетом включает сохранение приоритета на следующий день. Его можно нажать прямо в списке. Если он включён, удаление из плана не сбрасывает приоритет и добавляет задачу в план следующего календарного дня; уже заданный приоритет следующего дня сохраняется. Если выключен — при удалении из плана дневной приоритет сбрасывается на 4. При завершении задачи замочек выключается и становится недоступным.

Под названием задачи показана одна строка описания. Если текст длиннее доступной строки или содержит переносы, нажмите «Далее»: откроется отдельное окно с полным текстом и переносами строк. Закройте его крестиком или Escape. Для короткого описания кнопка не нужна, для пустого строка не выводится. Открытие описания не меняет данные и не запускает таймер.

4. Учитывать время и завершать работу

Итог времени за выбранный день расположен под заголовком «Мои задачи». Для текущего дня строка подписана «Сегодня».

  1. Нажмите ▶ в строке задачи. Время появится в панели текущего таймера.
  2. Для перерыва нажмите «Пауза» в панели или кнопку паузы в строке. Запись времени сохранится в истории.
  3. Чтобы продолжить, нажмите «Продолжить» или ▶. Начнётся новая сессия.
  4. Для окончательного завершения нажмите «Завершить» и при необходимости заполните результат.

Справа показана работающая задача, а если её нет — последняя вручную остановленная из задач, которые ещё на паузе. Учитывается нажатие «Пауза» и «Остановить таймер» в напоминании. Правка времени сессий не меняет этот порядок. После завершения или удаления выбранной задачи панель возвращается к предыдущей ручной паузе. Когда задач на паузе нет, написано «Молодец, все задачи выполнены!». Старые записи без истории нажатий и автоматические остановки не выбираются по времени сессии: приложение предлагает выбрать задачу. Одновременно учитывается одна работающая задача. Запуск другой приостанавливает прежнюю. Пауза не означает завершение задачи.

Всё время сессии относится к локальному дню её начала. При смене суток оставшаяся активной сессия прошлого дня закрывается в 23:59:59 того дня при обработке состояния. Начало новой сессии фиксируйте запуском таймера.

«Удалить» удаляет задачу вместе с её сессиями после подтверждения. Это отличается от удаления из плана. Перед массовыми изменениями сохраните JSON-копию.

5. История и ручное добавление времени

Нажмите название задачи или «История». В окне отображаются общий итог, сессии и комментарии.

  1. Нажмите «Добавить» в разделе сессий.
  2. Укажите начало и окончание. Проверьте дату и порядок времени.
  3. Добавьте комментарий: что сделано за этот промежуток.
  4. Нажмите «Сохранить».

Для исправления существующей сессии нажмите её «Изменить». Можно исправить время и комментарий. Удаление сессии требует подтверждения и убирает её время из итогов. Не записывайте один и тот же промежуток вручную и таймером, если не хотите двойного учёта.

При удалении сессии требуется подтверждение. После успешного удаления окно подтверждения закрывается. Если удалена последняя сессия, история становится пустой, а таймер задачи показывает 00:00:00. Саму задачу можно продолжить — начнётся новая сессия.

6. Концентрация

Нажмите верхнюю кнопку «Концентрация», задайте длительность от 1 до 180 минут и нажмите «Начать».

Текущая задача приостанавливается. Концентрация записывается отдельно, а её обратный отсчёт показывается в блоке «Текущая задача». Отдельной карточки концентрации нет.

По окончании время сохраняется. Кнопка «Остановить концентрацию» завершает её досрочно. После окончания можно явно продолжить последнюю остановленную задачу. При переходе суток учёт за прошлый день закрывается, обратный отсчёт продолжается до срока.

7. Напоминание «Продолжаете работать?»

Откройте ⚙ → «Продолжение работы». Включите вопрос и сохраните интервал от 1 до 1440 минут; по умолчанию — 40 минут.

После заданного интервала даётся 5 минут на ответ. Этот срок идёт даже при свёрнутом приложении или открытой другой форме. Позднее открытие окна не даёт новые пять минут.

  • «Продолжить» — работа продолжается, следующий вопрос будет через настроенный интервал.
  • «Остановить таймер» — текущая сессия заканчивается, задача не помечается выполненной.
  • Нет ответа — сессия закрывается по сроку автоостановки.

Пример: запуск в 10:00, интервал 40 минут → вопрос в 10:40, остановка без ответа в 10:45. Если вернуться в 11:00, лишние 15 минут не добавятся. При приостановке браузера запись будет обработана при возвращении. Концентрация этим напоминанием не управляется.

В настройках «Сигналы внимания» можно разрешить уведомления. Заголовок и название приложения привлекают внимание; системные сигналы зависят от браузера и разрешений.

8. Отчёт дня: текст и таблица

  1. Выберите дату и нажмите «Отчёт дня».
  2. По умолчанию откроется текст Markdown. Переключатель «Таблица» находится под заголовком того же окна.
  3. Включите «Расширенный», чтобы добавить описания, сессии и комментарии.
  4. Используйте копирование, скачивание или «Печать / PDF».

Копирование и скачивание сохраняют Markdown, в том числе при просмотре таблицы. Для красивого документа выберите «Таблица» → «Печать / PDF» и сохранение в PDF в диалоге печати браузера. Доступные пункты диалога зависят от устройства.

Оба вида используют один снимок данных на момент открытия. Если время или комментарии изменились, закройте отчёт и откройте снова. Отчёт учитывает день начала сессии.

9. Резервная копия и перенос

Откройте ⚙ → «Резервная копия данных».

  1. «Скачать JSON» — сохранить копию задач, сессий и комментариев.
  2. Сохраните файл вне данных браузера, например в папке документов или своём облаке.
  3. Для восстановления откройте приложение на нужном устройстве и выберите «Загрузить копию».
  4. Перед подтверждением сохраните текущие данные. Импорт копии заменяет локальное состояние, это не обычное добавление задач.

Используйте JSON, выгруженный этой PWA. Произвольный JSON или файл старой desktop-версии может быть несовместим. Перенос старых данных через WebDAV — отдельный механизм.

Кнопка «Защитить локальные данные» запрашивает постоянное хранение в браузере. Она не заменяет резервные копии и не создаёт облачную синхронизацию. Очистка данных сайта или профиля браузера может удалить локальные записи.

10. GitHub: обмен между устройствами

Обмен переносит также запуск, паузу и завершение таймера. После успешного получения изменений на другом устройстве используется та же сессия и время её остановки. В автоматическом режиме проверка идёт каждые 30 секунд при открытом видимом приложении, отправка правок — через 10 секунд. В фоне и без сети мгновенный обмен не гарантируется; можно нажать «Синхронизировать» на обоих устройствах.

Нерешённые конфликты полей сохраняются для выбора, но больше не запрещают получать остановку таймера. Для файлов до 20 МиБ поддерживается чтение большой версии по неизменяемому идентификатору GitHub. Удалять задачи или файл ради прежнего ограничения 1 МБ не нужно.

При конфликте показаны название задачи, понятное имя поля и варианты значений. Для приоритетов отображаются только различающиеся даты. Выберите нужный вариант: он будет сохранён целиком, затем синхронизируйте для передачи решения другим устройствам. Номер варианта не обозначает конкретное устройство.

Чтобы синхронизировать список задач, сессии и комментарии между компьютером и телефоном, сначала создайте отдельный приватный репозиторий GitHub и токен доступа к нему. На обоих устройствах используется один и тот же репозиторий данных. Репозиторий приложения и GitHub Pages не используются для хранения задач. По умолчанию обмен ручной. После настройки можно включить «Автоматическая синхронизация» на каждом устройстве.

  1. Откройте GitHub → New repository. Выберите свой аккаунт, задайте имя, например tasktimer-data, отметьте Private и включите Add a README file, затем нажмите Create repository. Запомните адрес в виде ваш-логин/tasktimer-data и имя ветки над списком файлов (обычно main). Если такой репозиторий уже создан, используйте его. Pages и Actions для данных не нужны.
  2. Откройте Settings вашего профиля → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Задайте имя, например TaskTimer Sync, и срок действия. В Resource owner выберите свой аккаунт, в Repository access — Only select repositories и только созданный репозиторий данных. В Repository permissions установите Contents: Read and write, затем нажмите Generate token. Скопируйте выданный токен в менеджер паролей. Он понадобится при настройке устройств. Не отправляйте токен в переписку и не добавляйте его в файлы репозитория.
  3. Откройте ⚙ → «Синхронизация через GitHub». Введите владелец/репозиторий, существующую ветку (обычно main) и токен. По желанию включите «Запомнить токен на этом устройстве», чтобы не вводить его после перезагрузки.
  4. Нажмите «Проверить подключение». Проверка только читает данные; разрешение записи окончательно проверяется при обмене.
  5. Нажмите «Синхронизировать». Перед первым обменом с этим ресурсом сохраняется локальная копия. Если файл отсутствует, приложение создаст data/state.v2.json; если существует — объединит изменения.
  6. На втором устройстве откройте ту же PWA и её настройки. Введите те же репозиторий и ветку, вставьте токен; при желании отдельно включите его сохранение. Нажмите «Проверить подключение», затем «Синхронизировать». При выключенном автоматическом режиме после изменений сначала выполните обмен на устройстве, где работали, затем на другом, чтобы оно получило изменения.

По умолчанию токен остаётся в памяти страницы и исчезает после закрытия или перезагрузки. Чтобы не вводить его каждый раз, включите «Запомнить токен на этом устройстве»: он будет сохранён отдельно для этого репозитория в браузере и автоматически подставится при следующем открытии. На другом устройстве сохранение включается отдельно. Снятие флажка удаляет сохранённую копию, оставляя введённый токен до конца текущей сессии; «Забыть токен» удаляет сохранённую копию и очищает поле. Если открыто несколько вкладок, забывание передаётся и в них. Токен не входит в JSON-копию, файл синхронизации и историю Git. Имя репозитория и ветка запоминаются на устройстве. Браузерное хранилище не является системным сейфом паролей: включайте сохранение только на личном устройстве и используйте токен с доступом исключительно к репозиторию данных. Забывание в приложении не отзывает токен на GitHub; срок действия и отзыв управляются в настройках GitHub. Названия задач, сессии, комментарии и удаления объединяются по журналу изменений; конфликтующие значения выбираются в настройках. Два одновременно работающих таймера требуют явного выбора одной сессии. Порядок списка, история ручных пауз и настройки напоминаний остаются локальными, но входят в PWA-копию.

«Копия до первого обмена» скачивает сохранённую копию для указанных репозитория и ветки. При последующих обменах она не заменяется. Это не замена регулярной кнопке «Скачать JSON».

При ошибке сети данные остаются локально. Если ответ на запись потерян, файл мог сохраниться: повторите «Синхронизировать», приложение сначала перечитает сервер. Неверный или просроченный токен замените в поле; при запрете доступа проверьте выбранный репозиторий, Contents и правила ветки. Публичный репозиторий не принимается. Не редактируйте файл обмена вручную. Поддерживаются файлы до 20 МиБ; при превышении обмен останавливается без перезаписи — сохраните JSON-копию и сообщите о проблеме.

GitHub хранит историю коммитов в приватном репозитории. Удаление записи из приложения сохраняет её удаление для синхронизации, но не очищает прежние версии из истории Git. При включённом автоматическом режиме обмен выполняется при открытии PWA с доступным токеном, после возвращения в приложение и восстановления сети. Сохранённые изменения отправляются через 10 секунд после последнего изменения; пока приложение видно, сервер проверяется каждые 30 секунд. Изменение цифр таймера само по себе не вызывает обмен. Неизменённый файл не записывается, лишние коммиты не создаются. Несколько вкладок этого экземпляра используют общий замок, поэтому ручной и автоматический обмен не идут одновременно. В браузерах без Web Locks API доступен ручной обмен. В свёрнутом или закрытом приложении выполнение не гарантируется — при возвращении проверка возобновляется. После сетевой ошибки попытки идут с увеличивающейся паузой; ограничения GitHub учитываются. При ошибке токена или конфликте автоматический обмен ждёт исправления. В верхней панели появляется «Синхронизация требует внимания» или кнопка разрешения конфликтов; откройте настройки. После исправления токена/доступа выполните ручную синхронизацию или переключите автоматический режим. Отключение режима отменяет текущий автоматический запрос, ручная кнопка остаётся доступной. WebDAV из настроек PWA убран; прежние данные приложения не удаляются.

11. Диктовка и обновления

Диктовка. В настройках «Офлайн-диктовка» сначала загрузите модель при наличии интернета. Начальная загрузка движка и модели — около 85 МБ, потребуется свободное место. Затем нажмите «Диктовать» у нужного поля, разрешите микрофон, запишите фрагмент и выберите «Остановить и распознать». Проверьте текст и нажмите «Добавить текст». Отмена оставляет исходное поле без изменений.

Поддерживаются название, описание и комментарий сессии; запись идёт фрагментами до 60 секунд. После предварительной загрузки распознавание работает локально, речь не отправляется в облачный сервис. Доступность микрофона и скорость зависят от устройства; качество текста проверяйте перед сохранением.

Обновления. Когда появится баннер с описанием выпуска, завершите редактирование и нажмите «Обновить». «Позже» откладывает текущую версию. Если баннер не появился, вернитесь в приложение при доступном интернете; проверка выполняется также периодически. Данные при штатном обновлении сохраняются.

Не очищайте данные сайта ради обновления. Для старой версии, ещё не умеющей показывать баннер, первое обновление выполняется прежним способом через настройки/повторное открытие. После установки версии с баннером следующие выпуски предлагают обновление в приложении.

Предупреждение браузера о закрытии не гарантируется на всех устройствах. Сохраняйте формы перед выходом; сворачивание в системный трей не предусмотрено.

13. Свой экземпляр через fork GitHub

Этот вариант позволяет получить свой адрес приложения и синхронизацию между устройствами без обслуживания собственного сервера. Приложение публикуется в GitHub Pages из вашего fork, а задачи хранятся в отдельном приватном репозитории данных.

Что потребуетсяДля чего
Учётная запись GitHubУправление своим экземпляром и данными.
Fork репозитория приложенияПубликация PWA и инструкции по своему адресу.
Приватный репозиторий с READMEОбщая база задач для ваших устройств.
Fine-grained tokenContents: Read and write только для приватного репозитория данных.
  1. Создайте fork приложения. Откройте репозиторий TaskTimer → Fork. Не ограничивайтесь копированием main: снимите «Copy the main branch only», если этот флажок показан. В fork должна присутствовать ветка pwa/development.
  2. Выберите ветку PWA. В Settings → General → Default branch своего fork назначьте pwa/development. Это позволяет обнаружить ручной workflow PWA; исходный репозиторий при этом не изменяется. Не переносите приложение в main ради публикации: там могут быть workflow прежних платформ.
  3. Разрешите публикацию. В Actions включите выполнение workflow своего fork. В Settings → Pages → Build and deployment выберите Source: GitHub Actions. Если окружение github-pages ограничивает ветки, разрешите выбранную ветку PWA.
  4. Запустите выпуск. В Actions выберите Publish PWA to GitHub Pages → Run workflow, ветка pwa/development. Дождитесь успешных тестов и Deploy GitHub Pages. Другие workflow Android/desktop для этого не запускайте.
  5. Откройте свою ссылку. Адрес будет указан в результате Deploy или Settings → Pages. Имя репозитория может отличаться: путь приложения и ссылка на инструкцию учитывают настройки Pages. При собственном домене настройте его и DNS отдельно.
  6. Подготовьте синхронизацию. Создайте отдельный приватный репозиторий с README и fine-grained token, затем настройте первое устройство по разделу 10. Приватный репозиторий данных не надо публиковать в Pages.
  7. Перенесите записи при необходимости. Если раньше использовали другой адрес PWA, сначала выполните обмен на старом устройстве и скачайте JSON-копию. В новом экземпляре можно подключить тот же приватный репозиторий и получить данные обменом. Повторный импорт JSON в этом случае не нужен. Для независимого нового набора данных используйте новый репозиторий и импортируйте копию один раз на первом устройстве.
  8. Подключите остальные устройства. Откройте именно новый адрес, укажите тот же репозиторий данных и ветку, введите свой токен доступа. Выполните обмен и сверку, затем отдельно включите автоматическую синхронизацию и, по желанию, сохранение токена на каждом устройстве.
  9. Проверьте экземпляр. Создайте задачу, запустите и остановите таймер, передайте изменения на второе устройство. Проверьте инструкцию, перезагрузку и офлайн-работу после первого открытия с сетью. Затем установите PWA средствами браузера.
  10. Получайте обновления. Fork сам по себе не устанавливает наши новые выпуски. Обновляйте ветку PWA из соответствующей ветки исходного репозитория, учитывайте свои изменения, затем запускайте публикацию и проверяйте результат. В исходном проекте push в pwa/publish запускает выпуск; для своего экземпляра выберите понятный порядок и проверьте triggers до push.

Локальные записи, токены и установленная PWA привязаны к адресу сайта. Новый адрес создаёт отдельное браузерное хранилище; старый экземпляр сохраняйте до сверки. Токен не добавляйте в код, публичный репозиторий, release notes или журналы. Для обмена он вводится только в настройках приложения.
