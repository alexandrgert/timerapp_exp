Этот вариант позволяет получить свой адрес приложения и синхронизацию между устройствами без обслуживания собственного сервера. Приложение публикуется в GitHub Pages из вашего fork, а задачи хранятся в отдельном приватном репозитории данных.

Что потребуетсяДля чего
Учётная запись GitHubУправление своим экземпляром и данными.
Fork репозитория приложенияПубликация PWA и инструкции по своему адресу.
Приватный репозиторий с READMEОбщая база задач для ваших устройств.
Fine-grained tokenContents: Read and write только для приватного репозитория данных.
  1. Создайте fork приложения. Откройте репозиторий TaskTimer → Fork. Не ограничивайтесь копированием main: снимите «Copy the main branch only», если этот флажок показан. В fork должна присутствовать ветка pwa/development.
  2. Выберите ветку PWA. В Settings → General → Default branch своего fork назначьте pwa/development. Это позволяет обнаружить ручной workflow PWA; исходный репозиторий при этом не изменяется. Не переносите приложение в main ради публикации: там могут быть workflow прежних платформ.
  3. Разрешите публикацию. В Actions включите выполнение workflow своего fork. В Settings → Pages → Build and deployment выберите Source: GitHub Actions. Если окружение github-pages ограничивает ветки, разрешите выбранную ветку PWA.
  4. Запустите выпуск. В Actions выберите Publish PWA to GitHub Pages → Run workflow, ветка pwa/development. Дождитесь успешных тестов и Deploy GitHub Pages. Другие workflow Android/desktop для этого не запускайте.
  5. Откройте свою ссылку. Адрес будет указан в результате Deploy или Settings → Pages. Имя репозитория может отличаться: путь приложения и ссылка на инструкцию учитывают настройки Pages. При собственном домене настройте его и DNS отдельно.
  6. Подготовьте синхронизацию. Создайте отдельный приватный репозиторий с README и fine-grained token, затем настройте первое устройство по разделу 10. Приватный репозиторий данных не надо публиковать в Pages.
  7. Перенесите записи при необходимости. Если раньше использовали другой адрес PWA, сначала выполните обмен на старом устройстве и скачайте JSON-копию. В новом экземпляре можно подключить тот же приватный репозиторий и получить данные обменом. Повторный импорт JSON в этом случае не нужен. Для независимого нового набора данных используйте новый репозиторий и импортируйте копию один раз на первом устройстве.
  8. Подключите остальные устройства. Откройте именно новый адрес, укажите тот же репозиторий данных и ветку, введите свой токен доступа. Выполните обмен и сверку, затем отдельно включите автоматическую синхронизацию и, по желанию, сохранение токена на каждом устройстве.
  9. Проверьте экземпляр. Создайте задачу, запустите и остановите таймер, передайте изменения на второе устройство. Проверьте инструкцию, перезагрузку и офлайн-работу после первого открытия с сетью. Затем установите PWA средствами браузера.
  10. Получайте обновления. Fork сам по себе не устанавливает наши новые выпуски. Обновляйте ветку PWA из соответствующей ветки исходного репозитория, учитывайте свои изменения, затем запускайте публикацию и проверяйте результат. В исходном проекте push в pwa/publish запускает выпуск; для своего экземпляра выберите понятный порядок и проверьте triggers до push.

Локальные записи, токены и установленная PWA привязаны к адресу сайта. Новый адрес создаёт отдельное браузерное хранилище; старый экземпляр сохраняйте до сверки. Токен не добавляйте в код, публичный репозиторий, release notes или журналы. Для обмена он вводится только в настройках приложения.
