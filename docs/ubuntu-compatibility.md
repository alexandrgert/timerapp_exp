# Запуск на Ubuntu 20.04 и новее (amd64)

## Причина и исправление

У опубликованного `.deb` 0.11.5 библиотека `libpython3.12.so.1.0` импортирует
`GLIBC_2.38`. Ubuntu 22.04 предоставляет glibc 2.35, Ubuntu 20.04 — 2.31.
В старом пакете также есть несовместимые Qt и системные библиотеки.
Смена одного `Depends` или установка дополнительных библиотек проблему не решает.

Linux собирается в `ubuntu:20.04`; CPython 3.12.14 компилируется там же из
официального архива с проверкой SHA256. Интерпретатор с хоста CI не копируется.
Linux использует PySide6 6.9.3 (manylinux_2_28), остальные ОС сохраняют 6.11.0.
`check_glibc.py` проверяет импорты версий всех ELF, включая вложенные библиотеки,
и блокирует упаковку при требовании выше glibc 2.31 либо неизвестном GLIBC ABI.
Проверка выполняется также перед созданием дополнительных Linux-форматов.

Launcher `.deb` работает вне Python/Qt: сохраняет stderr в приватный файл
`${XDG_STATE_HOME:-$HOME/.local/state}/timerapp-exp/launch.XXXXXXXX.log`,
показывает код завершения и путь журнала через zenity. Каждый запуск получает
свой файл с правами 0600; журналы старше семи дней удаляются при следующем запуске.
Данные приложения не перемещаются. При невозможности записи журнала сообщение
указывает на это, код завершения приложения сохраняется. `app.py` теперь
передаёт код возврата `main()` операционной системе.

## Причина первого сбоя и исправление

Полученный архив журнала подтвердил: Python и контейнер собраны успешно,
pytest завершился с **432 passed, 1 failed, 1 skipped**. Единственная ошибка —
`tests/test_formatting.py::test_format_task_datetime_from_iso`: в минимальном
контейнере отсутствовала системная база `tzdata`, поэтому `TZ=Europe/Moscow`
давал UTC (`17:31` вместо `20:31`). Пропуск относится к тесту Snap без snap/squashfs-tools.

В Dockerfile добавлен `tzdata`; перед тестами проверяется реальное преобразование
даты в Europe/Moscow с ожидаемым смещением +0300. Локально без сборки воспроизведено
поведение с пустым TZDIR и подтверждено правильное время с системной zoneinfo.
В preview workflow подготовка контейнера отделена от тестов/упаковки; журнал
тестов и упаковки сохраняется отдельным диагностическим артефактом.
Один повторный запуск уже разрешён пользователем.
